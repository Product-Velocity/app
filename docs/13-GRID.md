# Portfolio grid (issue #6)

Page: `/portfolio` ("Roadmap" in the navigation). Reference: prototype board 20, PRD §4.1 and §6, field dictionary `docs/reference/item-fields.csv`.

## What it does
- **Whole workspace loaded at once** (pages of 1,000 rows, filtered by tenant): items, the calculated view and the related tables. 2,000 items: load under 1 s, edits painted in a median 36 ms (p95 63 ms) in the browser test.
- **Every one of the 165 fields is a column.** Ten default views, each with an ordered column list from `docs/reference/default-views.csv` (Prioritisation, Planning, Delivery, Go-to-market, Outcomes, Leadership, Discovery, Timeline, History, Cycle review; decided 2026-10-23, R-021; the older "column lists of the workbook sheet" are superseded) and a Columns picker (show or hide). Fields of later phases show "Arrives in phase N" in the header. Stack Rank, Initiative ID and Initiative Name are always visible and pinned.
- **Autosave, no Save button.** An edit shows at once (optimistic), saves in the background, and the strip says "Saving…" then "All changes saved". If a save fails the old value comes back and the strip says why. Saves for one cell run in order.
- **Undo and redo:** ⌘Z / Ctrl+Z undoes the last of 20 changes, ⇧⌘Z / Ctrl+Y redoes. Each undo is its own audited write and only happens if the stored value is still the one being replaced (nobody else's change is overwritten). While typing in a cell the browser's own text undo is used.
- **Typed pickers** for selects, people, projects and yes/no: type to filter, arrows to move, Enter to choose, Esc to cancel. Option text is always shown, never colour alone (health has a label and a symbol).
- **Plain-language entry:** dates (`31 mar`, `next friday`, `q2`, `in 2 weeks`, `4/5` as day/month) and amounts (`120k`, `1.2m`).
- **Rank:** type a new global rank in the Stack Rank cell; the row jumps there, the others shift, the keyboard focus stays on the row. "In project" order recalculates.
- **Locked cells:** GitHub-driven, calculated, system-set and later-phase fields reject editing and say why under the grid. View-only roles (viewer, commenter, leadership) can look but not edit.
- **Keyboard:** Alt+N adds an initiative, arrows move, Enter or F2 edits, Enter saves and moves down, Tab saves and moves right, Esc cancels, Delete clears an optional cell (or, with the checkbox column or a read-only cell focused and rows ticked, asks to delete the ticked rows).

## Initiative Group: an open list (issue #38)
Initiative Group (`theme`) is an open list shared by the whole workspace (every project), not a closed list.
- **Typing creates.** In the grid picker (type to filter; a typed name that is not in the list shows "Create “name”"), in quick-add with `+group` (`+onb` = the group starting "onb"; dashes stand for spaces: `+platform-health`; an unknown name creates a new group and the chips say "(new group)") and in an import (the preview says which new groups will be created). The database adds the group the first time an item uses it (`items_ensure_group`) and keeps the existing spelling when only the case differs.
- **Near-duplicates.** Typing "On-boarding" next to "Onboarding" (same letters, or one typo in a name of 6+ letters) shows "Looks like “Onboarding”" before anything is created. Quick-add treats punctuation as no difference (`+on-boarding` is Onboarding).
- **Tidy-up (admins):** Account menu → **Initiative Groups** (`/settings/groups`): rename (every item in the group changes, one audited change per item), merge two groups (items move, the first group goes; **Undo** is offered right after, and only items still in the target move back), retire a group nobody uses. Groups that look alike are listed as merge suggestions. Everyone else sees the list without actions.
- Free-form **Tags** stay for other labels; Roadmap Category stays a fixed list of five values.

## Quick-add (issue #7)
A row above the grid. **Alt+N** puts the cursor there (⌥N on a Mac); type, press **Enter**, the item appears at the end of the list at once and is saved in the background; the cursor stays for the next one. Only the name is required.
- **Tokens** (anywhere for `#` and `@`, at the end for the rest): `#project` (letters of the name, spaces ignored, a unique start is enough), `@person` (start of the email name), a size in capitals `XS S M L XL`, and `must`, `should`, `could`, `won't`/`wont`. Example: `Faster search #market @bo M should`. A token that matches nothing, or more than one thing, is explained and nothing is added. The line shows how it was read ("Project: Marketplace · Product Manager: bo@… · Effort: M · MoSCoW: Should") before you press Enter.
- **Context:** without `#project` the item goes to the project of the row you are on in the grid; otherwise the project you used last; otherwise the only project there is. (Saved scopes and the scope switcher come with #9 and will then be the context.)
- **Paste a list:** several lines pasted into the row add one item per line (bullets and numbers removed, up to 200). Lines with a bad token are skipped and listed; the rest are added as one undo step.
- **Similar-item hint:** while typing, up to three existing items that share most of their words are shown ("Looks similar to: R-07 …"). It never blocks.
- **Search in long lists (R-018).** Any list with more than 8 options has a search box on top, focused when the list opens: it filters as you type (case-insensitive, anywhere in the name, every word must match, and the field key and import aliases count: "owner" finds Product Manager, "tshirt" finds Effort), Up and Down move, Enter picks, Esc closes and gives the focus back, "No results for “…”" is said in words. Applies to Group by, Filters (field and value lists), the bulk bar's "More fields" (field and value), the Columns picker (it filters the checkboxes), the import column mapping, the scope switcher, Views, and the pick-one fields in the item panel; the typed pickers in grid cells already filtered and now say "No results" too. Up to 8 options a list stays a plain select. One shared component (`components/search-list.tsx`, matching in `@pv/domain` `search-list.ts`). A ranked result list has no group headings.
- **Undo:** adding is one undo step; undo deletes the items again (ranks close up), redo adds them back at the end with new codes.
- **Audit:** the database records each new item (and every field) with who and source "UI". Not available to view-only roles.
- Plain text only: whatever is typed or pasted is a name, never an instruction. Pasting an email for AI intake is Phase 4.
- Admins can add a project by name from the Roadmap page (a minimal stand-in until project setup exists), because an item needs a project.

## Scopes, views, filters, grouping and the command palette (issue #9)
- **Portfolio scope** (the chip in the header, "All projects ▾"): All projects, a saved scope (a named set of projects) or a single project. The roadmap then shows only those projects' items; **ranks stay global**. The choice is in the address (`?scope=`), so a link shares it. "+ New scope" and "Edit" (rename, change projects, delete; asks first) are for creators and admins. Admins also get **"+ New project"** here. When the scope is one project, quick-add puts new items there.
- **Views.** The ten default views and "All columns" are chips. Anything you change (show or hide a column, drag a header to move it, add filters, group) is an unsaved change to the current view: a bar says so and has Reset. **Views ▾** lists the workspace's saved views and, for creators and admins, saves the current columns (in order), filters and grouping as a new view, updates, renames or deletes the open one. Saved views are shared by everyone in the workspace; a view does not store the scope. The open view is in the address (`?view=`).
- **Default views are generated, not typed.** The ten views (R-021, #54) come from `docs/reference/default-views.csv`, the workbook sheet "Default views (ordered)": `tools/field-dictionary/export_views.py` writes `packages/domain/src/default-views.json`, and a test fails on any difference in keys, order or pinned columns, or a key missing from `item-fields.csv`. Group, editing mode and customer-safe flags still come from "Grid columns and views" (`grid-views.csv`). Each view lists 15 to 25 columns; the first three are pinned. A view shows only the columns of phases that have shipped; the rest keep their place and appear when their phase ships, and a note under the chips names them ("N more columns of this view arrive in later phases"). Today (phase 1) live columns per view: Prioritisation 13, Planning 14, Delivery 7, Go-to-market 15, Outcomes 9, Leadership 14, Discovery 23, Timeline 12, History 17, Cycle review 8. Defaults live in code, so every existing workspace gets them with no data change; customised defaults and saved views are untouched. Creators and admins can **Change the default “X” for everyone** (stored as an override, audited) and **Restore the original “X”**; a changed default shows "changed by your workspace" on its chip. **Save current view as new…** duplicates any view.
- **Customer-safe views.** Tick *Customer-safe view* when saving: only fields the sheet marks customer-safe are kept (columns, filters, grouping), the database refuses any other column, and the Columns picker greys the rest with "not customer-safe". Target Markets and Live Markets are allowed (the sheet flags them customer-safe; Ashu confirmed). The pinned Stack Rank column stays visible in the grid itself but is not stored in a customer-safe view. Every role that can read the workspace sees every column in internal views.
- **Columns picker:** all 165 fields, grouped as in the sheet, later phases marked "arrives in phase N".
- **Filters** (all must match): choose a field, an operator that fits its type (is, is not, contains, greater/less than, before/after, is empty) and a value; dates take plain words; "me" works for people. Each filter is a chip with ×. **Search** looks in the code and name. A row you just added or imported stays visible even if a filter would hide it; rows you edit stay until you change the filter.
- **Group by** a list field, person, project or yes/no: a header row per group (count, collapse / expand). **Off by default.** Inside a group rows keep their rank order; empty values come last. While grouped, the global rank order is not applied across groups.
- **Command palette** (Ctrl+K / ⌘K, or the button): add an initiative, search, go to a view, scope or project, group by, clear filters and search, reset the view, import, export, undo and redo, open Members or Security, and find an initiative by code or name and jump to it.

## Item panel and item page (issue #26)
- **Opening.** Click an initiative's code (R-12) or press **Space** on any cell of its row: a panel opens beside the grid (440 px; the grid keeps working). **Esc** closes it. **J** / **K** (or the ↓ / ↑ buttons) move to the next and previous initiative in the order the grid shows now (scope, search, filters, grouping applied) without closing the panel; the grid scrolls to the row. While the panel is open, J and K navigate instead of starting to type into a grid cell. Clicking a name still only selects the cell, so it can be edited. The open item is in the address (`?item=R-12`): refresh or share it. **Open full page** goes to `/portfolio/R-12`, the same panel as a page with a shareable address (it respects roles; the code is looked up in the workspace you are signed in to).
- **Overview** shows all 165 fields grouped like the workbook (What, Who, Why, Decision, When, Go-to-market, Outcomes, Efficiency, Trust, Delivery (GitHub), Alignment, Spec, Planning, Gates; the first four stay open). Every shipped editable field has an editor with the same rules, autosave and undo as the grid: text, long text, number, currency and plain-language dates (blur or Enter saves, Esc cancels), selects, people, project, Yes/No, **Initiative Group** (open list, see above), **Stack Rank** (shown as "#3 globally · #1 in Platform"; type a number to move). GitHub-driven, calculated and system fields show their value, a badge and why they cannot be edited; fields of later phases show "Arrives in phase N".
- **List fields** have typed editors, each change one undo step (the strip's Undo, ⌘Z / Ctrl+Z): Tags, Target/Live Markets and Target Segments (chips, Enter adds), Artifacts (links need `http(s)://`, optional label), Depends On and Related To (initiative codes, no self-reference), Contributing Teams (checkboxes of the workspace's teams), Effort by skill (person-weeks per skill). The grid cell shows the list as text. **Screenshots** is read-only until file storage exists.
- **Health** has **Mark reviewed** (sets Last Reviewed to today) and a place for the suggestion banner ("Suggested health: Delayed", Apply / Dismiss), which stays empty until GitHub sync (phase 3).
- **Tabs:** Overview, **Spec** (empty until phase 4), **GitHub** (empty state with the epics-and-tasks columns of board 2, until phase 3), **Alignment** (empty until phases 5 and 8) and **Activity**: the audit log of this initiative (field changes, tags, links, relations, teams) with who, where it came from (UI, API, Claude, import) and when. **Undo** appears on your own change to a field while the field still holds the value that change set; changes to lists are undone with the strip's Undo. Activity is read through `item_activity` (migration 0014), so everyone who can read the item can read its history; the audit table itself stays admin-only.
- View-only roles can read everything and edit nothing. The prototype's tab "Fields" is the Overview here and "History" is **Activity** (the docs win).

## Bulk bar, export and import (issue #8)
- **Select rows** with the checkbox column (Space on the keyboard; the header checkbox selects all). A bar appears: "3 selected".
- **Set a field on all selected rows:** one button per common field (Health, MoSCoW, Horizon, Focus Area) opens the list of values ("Set MoSCoW on 3 items to", with "Currently: Must, Should, Could"); choosing a value applies it. "More fields" opens the general control for every other field: choose a field, choose or type the value, "Apply to 3 items". "Select all N" selects every item; Esc clears the selection. One validation for all rows, one undo step (⌘Z undoes all 3; the strip says "Undid: Set MoSCoW on 3 items"), one audited change per row and field. Rows that already have the value are skipped. If one row cannot be saved it goes back and the others stay. An empty value clears the field where that is allowed.
- **Rejected with a reason:** GitHub-driven fields (status, delivery progress, ...), calculated and system fields, fields of later phases and Stack Rank (one item at a time) are listed under "Cannot be set here"; choosing one shows why and the button stays off. The controller refuses them too, and the database column grants are the final gate.
- **Update GitHub** is a disabled button ("arrives in phase 3"). **Export selection to file** downloads a CSV of the selected rows with the columns you are showing (project and people by name; Excel opens it; text that looks like a formula is defused). Viewers can select and export but not edit.
- **Import from spreadsheet:** the button next to Columns, or paste cells copied from Excel or Google Sheets anywhere on the grid (Ctrl+V / ⌘V, not inside a text box). A dialog shows (1) how each column was read (guessed from the header names, changeable per column, "Do not import") and (2) a preview of the first 10 rows with the problems in words. Rows with problems are skipped; the rest are imported in one request (all or nothing), labelled "import" in the audit log, as one undo step. Up to 500 rows. Project names and people (email or the start of the email name) are looked up; a "project for rows that have none" can be chosen. If no header is recognised, tick "The first row has column names". Only fields a person can edit in a cell can be imported.

## Grid height
The grid fills the window below it (it grows with a taller window and shrinks with a shorter one, also while resizing, and follows bars that appear above it); minimum 360 px.

## Design pass 2 (request R-022, issue #55)
_Status: complete. Name, health pill and group summary rows in 0.14.0; the floating bars in 0.20.0._
- **Name:** Initiative Name is semibold/bold; IDs and other text stay regular.
- **Health pill:** compact (about 20 px high, 12 px text) so it fits a 30–36 px row; no icon. The word is the signal ("On track", "At risk", "Off track"); colours meet AA contrast on the pill background.
- **Group summary row** (only when grouped): only the group name, the item count and the health breakdown in words ("3 On track · 1 At risk"), computed on the filtered rows. No column aggregates. Collapse / expand stays.
- **Floating bars:** the bulk bar overlays the bottom of the grid area (fixed, centred, shadow) and never changes the grid height or scroll position; it appears with at least one selected row. The quick-add bar floats directly above the grid (and always above the bulk bar when both are shown (decided)) and stays visible while scrolling. The autosave strip stays where it is.
