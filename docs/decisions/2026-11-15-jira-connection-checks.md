**The Initiative-level checks of the J2 spike (#431) live on Settings > Integrations > Jira > Test connection, run on the stored connection, give pass / warn / fail with a reason and what to do, and are saved (issue #452).** Why: copying probe output between a throwaway page and chat is slow and error-prone, and the checks are useful to every workspace that uses the Initiative level, not only to us.

- **Checks (read only, `apps/web/src/lib/atlassian/jira-checks.ts`).** (1) a hierarchy level above Epic exists (fail with what to do if not); (2) two issue types sharing a name at different levels is a warning, "choose by level"; (3) an Initiative-level issue is found (or the key typed in); (4) its children are read with the same `parent in (...)` query as `jira-tree.ts`, with the number of projects they come from; (5) epics in projects that are not linked to Product Velocity get no webhooks (`project = KEY`), so that is a warning naming the keys; (6) what Jira hides from the sign-in cannot be counted, so this is always a warning that asks the admin to compare the count read with Jira's.
- **The write test is its own button**, behind a confirmation box that says it creates and deletes 2 test issues (label `pv-spike`), human admins only (not a service account, not Claude, not platform staff; the database function refuses them too). It reuses `probeInitiativeWrite`, which always deletes what it made, also on failure, and asks Jira's search again every 2 s for up to 10 s because the search lags about 2 s behind a write. A child never shown within 10 s is a fail; one shown after a retry is a pass that says the index lagged.
- **Saved results: `jira_check_runs`** (tenant, connection, time, human admin, kind read|write, JSON list of `{key, label, status, reason, fix}`). Written only by `jira_check_run_save()` (human admin of the workspace; audited, source UI), read by admins. Reasons are stripped of addresses and e-mails and capped at 400 characters; nothing holds issue text, people, tokens or site addresses. Rows are kept (a few kilobytes each); the page shows the latest run of each kind.
- **Claude reads them as the signed-in admin** (RLS: admins read the workspace's rows). **No MCP tool is added in this change**; if Claude should fetch them from a chat, that is a separate request (it would also need the Help page "AI agents" update).
- **Spike page.** The Initiative read probe and its links are removed from `/spikes/atlassian`; the write probe function stays because the checks reuse it. J3, J5, J6 and J8 stay where they are.
- **Parity exception (recorded, linked issue #454).** GitHub's Test connection page does not get the parent / sub-issue checks in this change: whether sub-issues span repositories of an organization is unverified and needs its own spike on a real organization. Everything else here (saved results, confirmation for anything that writes) is the pattern GitHub will follow.
- **Not built (optional slice 5 of the issue).** Running the read checks in the daily check and showing "Needs attention" on the Jira page: it touches the Jira tab and the daily check, which the #431 session is changing. Left open in the request file.
