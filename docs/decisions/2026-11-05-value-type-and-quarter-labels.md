**Roadmap Category is hidden; Business Value Type and Planned Quarter become labels; Focus Area also goes into a Jira text field (issue #324).**

- **Hide, not remove.** `HIDDEN_FIELDS` (packages/domain `registry.ts`) lists `roadmap_category`. It stays in the dictionary, the database, the CSV and the API (and in saved data), but is not shown: not a grid column, filter, group or sort, not in the item panel, bulk edit, default or saved views (`sanitizeView` drops it), nor in the Help columns table. Remove it from `HIDDEN_FIELDS` to bring it back. Its `pv:category/…` label and slots are retired: the next Sync removes a `pv:category/…` label from an issue, as it does any `pv:` label that no longer applies. Not changed: the Leadership "investment mix" chart still reads the field (it would now show "No category"); **to confirm** whether to replace it with Business Value Type.
- **Rule 2 exception: Business Value Type may leave as a label.** Business Value Type (New revenue, Increase revenue, Defend revenue, Decrease costs, Other) was "Never synced (commercial)". Ashu chose to send it as `pv:value/<type>`. It is a category, not an amount: Business Value (12m run-rate), Business Value Basis, confidence and every other commercial field stay never synced. `value_type` is removed from `NEVER_SYNCED` and added to both outbound allowlists; tests pin that the amount and basis never reach a payload. The switch is **off by default** per project (`github.label.value`, `jira.label.value`). **Repositories can be public: leave it off for those.**
- **Planned Quarter** (`g2m_quarter`, "Q3 2027") is sent as `pv:quarter/q3-2027`, **on by default** (a planning field, not commercial), switchable off per project (`github.label.quarter`, `jira.label.quarter`). Its own value, chosen by a person; the GitHub milestone still comes from G2M Date (est). Existing issues get the label at the next Sync.
- **Focus Area into Jira.** New slot `jira.focusArea` and the key `focusArea` in `jira_project_links.field_map` (a single-line text custom field, chosen per project in the field configuration, same list and rules as Theme; not sent until chosen). The `pv:focus/…` label is unchanged. **Theme already receives the Initiative Group name** (decision 2026-11-03-jira-theme-field), so Focus Area has its own field choice: if a person picks the same Jira field for both, the Initiative Group wins and the preview says Focus Area was not sent. To put Focus Area into Theme instead, choose Theme for Focus Area and another field for the group.
- **Parity.** Labels built for both trackers. The Jira text field has no GitHub twin (GitHub has no Theme field; the Project board Initiative field already carries the group). Exception, reason: no such field on GitHub issues.
- **Migration** `20261105162014_value_quarter_labels_focus_field.sql` replaces `tracker_set_field_config` (slot list; default-off list) and `jira_set_field_map` (key `focusArea`); same permissions. Saved rows for the retired category slots are ignored and deleted at the next save.
