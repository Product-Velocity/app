**Reading Jira (issue #67 slice C1, #69).** An admin presses "Read Jira now" on a linked project; the app reads the project's OPEN work (status category not Done), up to 1,000 issues, newest first, into a light record per issue in `jira_issues` (key, title, type, level, labels, status and status category, parent, link). Every issue starts as **Not pulled**: nothing enters the roadmap, a grid, a rank or a report, and nothing is written to Jira. This is the Jira twin of `tracker_issues`; GitHub stays untouched (router, 2026-10-29).

- Compare before write: an unchanged issue costs no write; a later read never changes a known issue's pull state; an older answer never overwrites a newer one; a link reads its own Jira project only.
- Text from Jira is data: titles are cleaned (control and direction characters removed, 300 characters) and never interpreted.
- Not in this slice: pulling issues in with ownership (slice C2, in the "new items" step of Sync and on the Incoming page through the router), issues that became Done since the last read, webhooks (J3) and a daily check.
