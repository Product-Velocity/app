**PV skills: `pv-<skill>` commands in the MCP connector.** Decided on issue 565; design in `docs/31-SKILLS.md`.

- A skill is one typed spec in `packages/domain/src/skills*.ts`; one builder turns it into the prompt. It is served through the same two doors as the other flows: MCP prompt (Claude, Gemini) and `get_playbook` (ChatGPT and other clients). Syntax: `pv-<skill> [target] [your words] [--draft]`.
- `get_playbook` stays hidden from Claude and Gemini (`2026-11-17-connector-directory.md`). In Claude and Gemini a skill is started from the prompt picker; typing the command works where `get_playbook` is listed.
- Our own wording and structure. No outside text is copied and no outside source is named in product copy or docs.
- Skills never set Stack Rank, Value, Confidence or Decision and never approve; scores are advisory. Documents never reach GitHub (rule 2).
- A skill's "decision" line names a person role ("To be decided by"); gates stay the only place decisions are made.
- Slices built now: 1, 2, 3, 5 (see the request). Slice 3 adds a workspace-level documents table that also holds the company documents.
