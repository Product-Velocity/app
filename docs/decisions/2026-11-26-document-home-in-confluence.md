**A document or link can have a home in Confluence, with two settings: who is the source, and whether it stays in sync (issue #693).** It extends J7 (`2026-10-29-confluence-publish.md`), where PV was always the source, so that either side can be.

| Source | Updates | What happens |
|---|---|---|
| Confluence (pull in) | Once | PV imports the page text as a document version, then unlinks. |
| Confluence (pull in) | Keep in sync | PV rereads the page on Sync, in the daily check and when Claude asks. A new page version becomes a new PV version. PV never writes back. |
| PV (publisher) | Once | PV creates the page from the document, then unlinks. |
| PV (publisher) | Keep in sync | Each new PV version becomes a "To send" entry in the Confluence preview; nothing is written until a person confirms. |

- **Document kinds on links.** Links and files carry the same document kind as written documents (PRD, Business case, Go-to-market, and so on), so PV and Claude know where the latest document of a kind is, whichever side holds it. This reverses "document kinds apply to written documents only" from `2026-11-05-spec-attachments.md` for the kind field; a link without a kind stays valid.
- **One side is the source per document.** Editing the same document on both sides is not built. If both sides changed since the last sync, the person gets a conflict card (Keep PV, Keep Confluence, or import the page as a new draft version).
- **Unlinking** is possible at any time. PV keeps its last copy; the page stays. Switching a document's sharing off still ends its public link at once.
- **Claude** can prepare a link, a kind, a source and a sync setting, and a publish target; a person confirms every Confluence write and cannot be replaced by Claude (rule 3). Page text read back is data, never instructions (rule 4). Every read that changes PV and every write is audited with source and, for MCP, the AI name and model (rule 5).
- **Approved documents.** If a document was accepted at a gate and a newer text arrives from Confluence, the new version is a draft and needs re-acceptance (approval is about the text).
- **Who may.** Any Creator can link and read. A Confluence write needs the confirmation in the sync preview.
- **Commercial text.** Confluence is the customer's private site (exception in `2026-10-29-confluence-publish.md`); the preview warns about customer names, value and key results. Cached page text never enters a GitHub or Jira payload (the shared-document readers stay the only readers of `item_documents`, and the cache is not read by them).
- **Parity.** Atlassian only, because GitHub has no hosted document store. Follow-ups for GitHub wiki and Notion are separate issues.
- **Slices.** A: kind on links and files, and reading a linked Confluence page (source Confluence, once or keep in sync). B: publish from PV (J7, #258). C: Claude flows and Help pages.
- **[SPIKE] open:** reading a page body through the Confluence API (scopes beyond the summary scopes already requested; storage format to Markdown is lossy: macros and layouts do not round-trip). Slice A builds the read behind an interface and records the result here.

**Slice A, split while building (2026-11-26).** A1, built: `item_attachments.doc_kind` (links; files later), `Link.kind` in the domain, a kind picker on the Spec tab, `add_link {kind}`, and the kind in `get_item` and `list_documents` (`linked_documents`). The kind is not sent to GitHub or Jira. An existing link keeps its kind when `add_link` is repeated; only a person changes it, on the Spec tab (no MCP update path, so no new undo case). A2, not started: reading the text of a linked Confluence page. It is a **[SPIKE]** (docs/08): the page-body read and its scopes are unverified, and no Confluence site is reachable from the build environment, so it waits for a spike run against a real site.

**Slice B: build now, no separate spike (Ashu, 2026-11-26).** The J7 spike never ran (the sandbox Jira site has no Confluence, `docs/08`). Ashu decided not to run a separate spike: slice B is built from the Confluence Cloud REST API documentation and tested within the first customer project, which has Confluence linked and will be the first user. What that means: (1) the live calls are the unverified part, so every request and response is checked defensively and every failure is shown in words, never swallowed; (2) every Confluence write still needs a person's confirmation after a preview, so a wrong guess costs a refused preview, not a wrong page; (3) results of the first real publish (scopes that were needed, page format that worked, limits) are written back here and in `docs/08` under J7; (4) no customer content, page ids or site names are committed (the repository is public until go-live).

**Slice B, as built (2026-11-26).** Table `item_document_pages` (one live publication per document, history kept; the database refuses an assistant, PV035). Two steps: a preview returns a token over the document version, the target, the page body and the page's version; "Confirm" writes only when the same token comes back, so what is written is what was seen. Conflict (the page's version moved since our last write) is refused unless the person chooses Keep Product Velocity; a deleted page makes a new one. **Not built, decided to leave out of this slice:** "To send" entries for keep-in-sync documents in the Sync dialog (today the document shows "page out of date" and the update is one click plus a confirmed preview), importing the page text (slice A2), images and attachments, workspace documents, the Claude flow (slice C). Rules kept: a Creator or Admin who is not a service account and not platform staff; the text goes only to the customer's own Confluence after a preview, never to a tracker payload (a test keeps the Confluence code apart from the GitHub and Jira code); the commercial warning uses the key-result name, the value and money amounts (customer names are not stored as a list, so they are not scanned); the sign-in asks for the three classic Confluence scopes only when an admin chooses "Add Confluence", and signing in to Jira again keeps them. **Open (decision 2026-11-26): the first real publish in the first customer project settles the scopes, limits and page rendering; write the result into `docs/08` (J7).**

**First real publish, 2026-11-26 (first customer project).** Two faults, both ours. (1) The space list used the v1 endpoint `/wiki/rest/api/space`, which Confluence has removed (410 "This deprecated endpoint has been removed"). The client now uses only the v2 API: spaces by key or list, pages by id, a page created in a space **by its id**, an update carries the next version number. A 410 is now shown as "no longer supported, a fault in Product Velocity", not as a problem of the customer's Confluence. (2) The kind picker added to link rows (slice A1) made the row grid wrap, so the "⋯" menu opened off the window: link rows now have their own five-column grid, and any row menu that would leave the window opens the other way. Lesson written into `docs/08` (J7): the Confluence v1 endpoints are not safe to use.

**Slice C, as built (2026-11-26).** Claude asks, a person confirms. A request (table `item_document_publish_requests`, one open request per document, written by a person or by Claude as the signed-in person, source and AI model audited) stores where, once or kept in sync, a title and a one-line reason; it holds no text and sends nothing. MCP: `request_confluence_publish`, `withdraw_confluence_request`, an optional `publish` on `create_document`, and `confluence` / `publish_request` on `list_documents` and `get_document`. The argument is `after_publishing` (`keep_in_sync` or `once`), not `mode`, because the tool lists must not carry a `mode` key. In the app the document row shows "Publish requested by Claude", the dialog opens filled in, a confirmed publish clears the request, and the person can dismiss it. **Approval (Ashu asked, 2026-11-26):** publishing does not need an approved document. A decision gate approves only the Discovery document (Gate A) and the PRD (Gate B); no gate approves other kinds, so their hint now says so instead of promising an approval at Design to Build. A general per-document approval by the Approver permission is **not built**: it would change "a document is never approved anywhere else" (`docs/28-DECISION-GATES.md`) and needs Ashu's decision.

**Confluence gets its own connection (Ashu, 2026-11-26).** After the v2 fix the first real site answered 401, and the only way to change the permissions was to disconnect Jira, which deletes the project links and mapping of projects without linked initiatives (`jira_disconnect`), so the whole Jira set-up had to be redone. Decided: (1) **Confluence is a separate connection** (tables `confluence_connections` and `confluence_credentials`, migration `confluence_connections`; one live connection per workspace; its own settings page with Connect, Reconnect, Test connection and Disconnect; the Jira connection, project links and mapping are never touched). (2) **Reconnect keeps everything**: signing in again replaces the live connection in place for both Jira ("Reconnect (keeps your settings)") and Confluence; Disconnect says what it removes. (3) The Confluence connection asks for the **granular** permissions `read:space:confluence`, `read:page:confluence`, `write:page:confluence` (the classic ones got "scope does not match"); the page lists which were granted and which are missing. (4) A 401 from Confluence shows Atlassian's own reason instead of "sign in again". Publications point at the Confluence connection (`item_document_pages.connection_id`, the old constraint was replaced by one that does not check rows written before). The Confluence permission on the Jira sign-in ("Add Confluence") was removed. **Open:** that the three granular permissions are enough on the first real site (the Test connection button answers that).


**Slice A2, as built (2026-11-26).** The spike question (can the page body be read, with which permission) is answered by the first real site: v2 `GET /pages/{id}?body-format=storage` with `read:page:confluence`. A person imports a page into a new document (preview, then Confirm; created "Do not share"), or checks a kept document for a newer page version (preview, then Confirm adds a version). The page is never written by this path. Claude can only read a page that is already linked (`read_confluence_page`); it does not browse Confluence, import or refresh. Images and attachments are not carried over.
