**The platform owner administers accounts and their people from the All accounts console.** Ashu asked for the console as an AG Grid and for the owner to see and add members, invite them, pause access and delete an account. Two parts of this reach past what `docs/15` section 5b promised customers, so he decided them (2026-11-22):

1. **A narrow exception to "platform admins never change members".** A platform admin may, from the console and only through five audited functions: list the people and pending invitations of an account (opening the list is written to the configuration log), **invite** a person (the link is always returned once; the email goes out only after the owner chooses "Send invitation email", with a sender line naming Product Velocity), **renew** or **cancel** an invitation, and **pause, resume, revoke or restore** a person (same status table as the Members grid; the last active admin is protected by the existing trigger). They never change a role, never set or grant **Approver**, never touch a service account, and never read a secret. The functions require a sign-in within the last 15 minutes and refuse when platform access to that account is restricted to read-only. Every action is written to the account's audit log as a Platform admin and to the configuration log. The table triggers that refuse member writes by an admin who has entered the account (`PV022`) stay in place for every other path; only these functions set a transaction-local flag that lets their own write through. Customers' admins see the entries in their audit log, as before (FR-2.9).
2. **Pause access.** `tenants.suspended_at` (migration `20261122153043_platform_accounts_console.sql`). While set, the access helpers (`is_tenant_member`, `my_tenant_ids` and the rest) give nobody a membership, so members see nothing and are shown "This account is paused" instead of onboarding; every write by a signed-in person who is not a platform admin is refused (`PV025`, a trigger on every tenant table, with a test that fails if a new table lacks it); platform admins can still enter. It is reversible with Resume; the optional reason goes to the configuration log and the account's audit log, never to the members. **Not stopped:** jobs that run with the service role (GitHub and Jira webhooks and scheduled sync) are not signed-in users and keep running; stopping them is a follow-up if a paused account must also stop syncing.

Also decided: "company name" is the account name (one organisation name per account); Company URL is `tenants.company_url`. The grid is client-side with the whole list loaded (up to 2,000 accounts), like the Roadmap grid.
