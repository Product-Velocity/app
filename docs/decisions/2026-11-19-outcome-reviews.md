**The 30, 60 and 90 day outcome reviews exist, and the first action asks for them.** Ashu asked whether the 30/60/90 metrics fields existed; they did not (the outcome fields are phase 7 of `docs/06-BUILD-PLAN.md`), so they are built now, together with the first action, as he asked. This pulls one slice of phase 7 forward; the rest of Outcomes (metric ingestion, the Outcomes tab, the learning loop) is unchanged and still later.

- **Not a gate** (`docs/28-DECISION-GATES.md`). A review is due 30, 60 and 90 days after **Start Roll-Out**. An initiative with no Start Roll-Out has no review.
- **What a review records (Ashu's choice):** the realised value of the Primary KR, the adoption %, and a note (up to 2000 characters). Stored in the new table `outcome_reviews` (one row per initiative and checkpoint; `docs/03-DATA-MODEL.md` already named it), written only by `request_outcome_review` and `record_outcome_review`, read by workspace members (RLS, fast pattern). Audited like every write. Outcomes are never synced to GitHub or Jira (rule 2): the table is in no tracker payload.
- **Who is asked (Ashu's choice):** the **Product Manager** (`owner_user_id`), else the person who created the initiative, with an in-app notification ("R-1 Faster onboarding: the 30 day outcome metrics were requested. Please record them."). Business Owner is free text, so it cannot receive one. Asking yourself sends no notification.
- **Who may ask and record:** a Creator or Admin, as for a gate request. **Never Claude or a service account** (`PV004`): asking sends a notification to a person, so a person does it. A second request for the same checkpoint is refused (`PV006`).
- **The flags (Changes report and Roadmap grid Flags column):** **Outcome review due** (Roll-out or Completed, the earliest unrecorded checkpoint is due within 7 days or late, nobody has asked yet), with the action **Request 30-day metrics** (60 or 90 for those checkpoints); then **Outcome metrics requested**, with the action **Record metrics**, which opens the initiative. A recorded checkpoint moves on to the next. These flags need the reviews to be loaded; a screen that could not load them shows no outcome flag rather than a wrong one. The Needs attention page is unchanged. The 7 days lead (`OUTCOME_LEAD_DAYS`) is a default.
- **Where to record:** the item panel has an **Outcome reviews** section for an initiative in Roll-out or Completed with a Start Roll-Out: the three checkpoints with their due date and state in words, Request metrics, Record and Edit.
- **Not in this change:** the columns of the dictionary's outcome fields (Outcome Status, Outcome Review Date, Realized KR Value and so on) are still later; a Claude tool to read or record reviews (the MCP server, and with it the Help pages for Claude); the Outcome reviews in reports; an email for the request (the notification is in-app only).
