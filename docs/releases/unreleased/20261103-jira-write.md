**Sync can now send to Jira (issue #67 and #71, the write half).** For an initiative that Product Velocity owns, "Sync with Jira" reads the issue first, then shows Received, Conflicts and To send. You choose Keep Product Velocity or Keep Jira for a name or description that changed in Jira, press Apply and send, and the dialog writes one initiative at a time ("Writing x/y") with a result and Try again for each. It sends the name, the description (converted to Jira's format; a description is rewritten only when its text changed since the last sync, so tables and macros in Jira are never flattened by accident), `pv:` labels, the due date (G2M Date), and, where the Jira site has them mapped, start date and priority. An initiative of a Jira-linked project with no issue gets one created in the linked Jira project. Status is never written, no workflow transition is ever made, and value, confidence, customers, decisions and other commercial fields can never go out (a test fails if one does). Jira's rate limit is waited out, and a connection that needs a new sign-in is shown, never retried. Migration `20261103094723_jira_sync_write.sql`.
